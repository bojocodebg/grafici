# Графици – Денонощни аптеки „Пулс“

Уеб система за работни графици на служителите (Next.js 16 + MySQL/MariaDB).

## Функции

**Всеки служител (без допълнителни права):**
- преглед на месечния график на своята аптека (само четене). Под името на всеки служител има часове по вид смяна (напр. `Д: 48 ч  Н: 24 ч`) и общо за месеца; плюс списък „Моите смени“;
- изпращане на забележки (задължително за конкретна дата, формат дд.мм.гггг) и преглед на забележките на всички служители. Забележките се показват в графика с червена точка (забележките на администратора – на отделен ред „Администрация“ в графика на всяка аптека) – при задържане на мишката излиза балон с текста и линк към забележката. Редакция и изтриване – само администратор;
- подаване на заявки за отпуск (платен, неплатен, болничен, друг) – след подаване не могат да се променят;
- смяна на собствената парола.

**Административна част – права, задавани поотделно на всеки потребител:**

| Право | Какво позволява |
|---|---|
| Администратор | пълен достъп до всичко |
| `schedule.view_all` | преглед на графиците на всички аптеки |
| `schedule.edit` | попълване/редакция на графика, копиране от предходен месец |
| `leave.approve` | одобряване/отказ на отпуски (одобрените се виждат в графика като „О“) |
| `notes.manage` | отговор на забележки и отбелязване като прегледани |
| `users.manage` | създаване/редакция на потребители и техните права |
| `pharmacies.manage` | управление на аптеки, длъжности и типове смени |
| `audit.view` | преглед на журнала с действията (филтри + експорт в CSV) |

Правата се проверяват на сървъра при всяко действие и промяната им важи веднага.

## Служители във всички аптеки

Служител с длъжност, отбелязана **„Във всички аптеки“** (по подразбиране „Управител“), или служител **без зачислена
аптека** се показва в графика на всяка аптека и може да получава смени във всяка от тях. За един ден може да има
само една смяна: ако вече има смяна в друга аптека, тя се вижда избледняла, а при промяна системата пита дали да
бъде преместена. Покритието на аптеката брои само смените в нея; часовете на служителя са общо за всички аптеки.

Редът на служителите в графика се задава с поле „Ред в графика“ (в профила или наведнъж от списъка с потребители).
Служебни акаунти (напр. `admin`) не се показват в графиците – в профила е изключено „Участва в графиците“.
Потребител, който има смени в графиците, не може да бъде изтрит (бутонът е неактивен) – може да се деактивира.

## Автоматичен изход (session timeout)

Важи **само за служебния акаунт `admin`**. Останалите потребители **нямат ограничение във времето** – остават
влезли до „Изход“ (бисквитката се подновява автоматично). Смяна на паролата (от администратора или от самия
потребител) и деактивиране прекратяват веднага всички други сесии на потребителя.
Страница **Настройки** (само за администратор): време за автоматичен изход при неактивност (5–1440 мин, по подразбиране 30)
и колко секунди преди това да се покаже предупреждение с обратно броене („Продължи работа“ / „Изход“).
Активност (мишка, клавиатура, докосване) във всеки раздел на браузъра удължава сесията и в останалите.
Сървърът също проверява неактивността при всяка заявка. Изходите поради неактивност се записват в журнала.

## Удобства в графика

- Последно избраните месец и аптека се помнят (в браузъра) – след друга операция, меню, нов вход и т.н.
  графикът се отваря отново на тях. „Текущ“ връща към текущия месец.
- „Изчисти месеца“ изисква двойно потвърждение: въпрос + прозорец, в който се пише `DELETE` с главни букви.

## Журнал на действията

Всяко действие се записва в таблица `audit_log`: вход (успешен/неуспешен), изход, добавяне/редакция/изтриване
на смени, забележки, отпуски (вкл. одобряване/отказ), потребители и права, аптеки, длъжности, типове смени,
смяна на парола, копиране/изчистване на месец. За редакциите се пази „преди → след“, плюс IP и устройство.
Страница **Журнал** (`/admin/zhurnal`): филтри по потребител, обект, действие, период и текст; експорт в CSV за Excel.

## Дизайн

Mobile-first, fluid и responsive: плавна типография и отстъпи (`clamp()`), container queries за таблиците
(при малко място редовете стават карти) и за графика (на тесен екран – изглед „По дни“, с ръчен избор
„Таблица / По дни“), сгъваемо меню на телефон и таблет, долен панел за избор на смяна на телефон.

## Инсталация

Изисквания: Node.js 20+ и MySQL 8 / MariaDB 10.6+.

1. Копирайте `.env.example` като `.env.local` и попълнете паролата на MySQL потребителя (`root`) и базата (`grafici`).
   **Задължително сменете `SESSION_SECRET`** с дълъг случаен низ. При работа през HTTPS задайте `COOKIE_SECURE=true`.
2. Инсталиране и създаване на базата, таблиците и началните данни:
   ```bash
   npm install
   npm run db:init
   ```
   (схемата е и в `sql/schema.sql`, ако предпочитате да я пуснете ръчно)
3. Стартиране:
   ```bash
   npm run build && npm start      # продукция, порт 3000
   npm run dev                     # разработка
   ```
4. Вход: **admin / admin123** – сменете паролата веднага от „Моят профил“.

## Обновяване

След `git pull` изпълнете отново:
```bash
npm install
npm run db:init
npm run build
```
`npm run db:init` е безопасен за съществуваща база – добавя само липсващите таблици/колони
(напр. мигрира старите текстови длъжности към таблица `positions`), без да трие данни.

## Структура

- `sql/schema.sql` – таблици: `pharmacies`, `positions`, `users`, `user_permissions`, `shift_types`, `shifts`, `notes`, `leave_requests`
- `scripts/init-db.mjs` – създаване на схемата + админ, примерни аптеки и смени
- `lib/` – връзка с БД, сесии (JWT в httpOnly бисквитка), права
- `app/(app)/grafik` – графикът (редактор с избор от прозорец или „четка“ за бързо попълване, покритие по дни, печат A4)
- `app/(app)/zabelezhki`, `app/(app)/otpuski` – забележки и отпуски
- `app/(app)/admin/*` – потребители и права, аптеки, длъжности, типове смени
